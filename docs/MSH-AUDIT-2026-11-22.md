# MSH audit — 22 November 2026 — the gate that had been green for eighteen days

Owner instruction, 19 November 2026: *massacre spatial hallucinations and kill
all the AI design slop; the real estate economy for the screen is very
important; make sure that the whole thing works really well from an operational
point of view.*

This audit is about the **gates**, not the interface. The interface was measured
on 19 November and fixed. This one found that three release gates had stopped
being able to see anything at all — and that what they could no longer see was
a real defect on every phone size.

## Found

**Three gates certified a layout the site stopped serving on 4–5 November 2026.**

| Gate | Receipt | Measured against |
|---|---|---|
| `check-orchestration-geometry.mjs` | `docs/evidence/orchestration-2026-11-04/` | `index-CfKJvUMe.js`, commit `cba3c71` |
| `check-resume-evidence.mjs` | `docs/evidence/resume-audit-2026-11-03/` | `index-Nh6bqPhD.js` |
| `check-manga-evidence.mjs` | `docs/evidence/recovery-2026-11-05/` | `index-D22cXYjY.js`, commit `9d53bd2` |

All three reported **PASS**. All three asserted against a bundle the site no
longer served — the same fault `check-served-bytes.mjs` was written to catch on
13 November, still open for these three. Their receipts had no producer: they
were taken by hand in a connected browser, so they could not be refreshed at
all. The resume audit's own README says so: *"The Python capture helper is
optional and was not executed during this audit; actual UI interactions used
the connected browser."*

**What the stale gates were hiding.** Refreshing the receipts against the live
site turned the orchestration gate red, with the name of the defect in the
message:

```
AssertionError: escape-en: first direction cue missing
```

Measured on the live release, on every phone size:

| Viewport | Cue at | On the screen? | Escape flow |
|---|---|---|---|
| 390 × 844 | x = 406 | **no** | 10 pages |
| 320 × 700 | x = 339 | **no** | 10 pages |
| 390 × 600 | x = 406 | **no** | 10 pages |
| 667 × 375 | x = 683 | **no** | 5 pages |

The reader pressed **Start** and could not see which way to turn. The 4 November
receipt recorded the cue at x = 8 — on the screen — so the phone layout changed
after that receipt was taken, and the gate that would have noticed could not.

**The cause.** The phone's reading column is 130px tall, and the warning lesson
fills one column whole (130px, `break-inside: avoid`). The cue (42px) therefore
fell into the next column, one page away. The map stays at 60dvh and the
operations panel stays at its measured 205px; neither is the fault, and
neither moves.

**This was not caused by the 19 November release.** The previous release
(`40f7bbf`) was built and measured for this audit: ten escape pages and the cue
off screen at the same four sizes. The 19 November release reduced the escape
flow to eight pages but left the cue one page away. The defect predates it.

## Changed

- **`src/EscapeGuide.tsx`** — the live direction cue now opens the escape
  guide; the warning lesson follows it immediately below. The phone's own rule
  (7 November: *"big containers may split across pages; only small atoms stay
  whole"*) lets the warning lesson break across the page boundary, so the
  first page carries the cue and the head of the warning.
- **`scripts/capture-geometry-evidence.py`** — a producer for all three geometry
  receipts. It writes the same files, in the same shape, with the same row
  counts, so the three gates are untouched and now have receipts that can be
  refreshed.
- **`scripts/check-served-bytes.mjs`** — the geometry evidence's byte receipt
  is now checked, so those three gates cannot certify a release they did not
  measure.
- **`package.json`** — `npm run release` now refreshes the playback receipt and
  the geometry receipt and runs the Results pagination gate. **Before this it
  could not pass**: it deployed, refreshed the viewport receipt, and then ran a
  byte gate that also checks the playback receipt — which the release never
  refreshed. The chain failed on itself.

## Verified

Measured on the patched build in Chromium, one fresh context per viewport so
that no pager state carried over:

| Viewport | Cue at | On screen | Start on screen | Escape pages |
|---|---|---|---|---|
| 390 × 844 | x = 8 | **yes** | yes | 8 |
| 320 × 700 | x = 8 | **yes** | yes | 8 |
| 390 × 600 | x = 8 | **yes** | yes | 8 |
| 667 × 375 | x = 369 | **yes** | yes | 5 |
| 1024 × 768 | x = 748 | **yes** | yes | 2 |
| 1440 × 900 | x = 1028 | **yes** | yes | 2 |

Every escape page measures **100% fill** with no void at 390×844, 320×700,
390×600, 1024×768 and 1440×900. `document.scrollHeight` equals the viewport
height at every size: no document scroll.

Also on the patched build: `npm test` — 91 TypeScript and 11 Python tests pass;
`node scripts/check-contrast.mjs` — exit 0; `npm run verify:pages` —
**PAGE_FILL_PASS**, 40 pages, 0 blank, 0 holes, 0 fragments.

**The gate itself was proved to fail on the defect.** Before the fix, with
receipts measured on the unpatched build, `check-orchestration-geometry.mjs`
failed with *"escape-en: first direction cue missing"*. A gate that cannot fail
on the defect it was written for is not evidence; this one can.

## Remaining

1. **The three refreshed gates are the evidence for the current release only.**
   They are produced by one script now, so they can be refreshed; but they are
   still receipts, and a receipt is only evidence for the bytes it measured.
   `check-served-bytes.mjs` is what keeps that honest, and it now covers them.
2. **The phone's escape guide is eight pages.** Every page is full, and the
   page count is the guide's own length — the drill protocol, the route
   profile, the scrubber and the method. Shortening it would mean cutting
   content, which the rules forbid.
3. **Owner-side, unchanged:** the physical-phone touch test at 390×844, GPU
   frame pacing on real hardware, and the Thai pagination reading test. Every
   width in this record is an emulated viewport.
4. **Roof coverage unchanged:** 8 readings against 1,196 buildings.
5. **No real research replay ships with the app** — schema, import path and
   synthetic fixtures only.
6. **The Rokehan embed** still needs one line changed by that tool's author:
   `frame-ancestors 'self' https://oyasumi-gamedev.com https://tsunami.nonarkara.org`.
7. **Two receipts still have no producer**: the escape-sync audit
   (`scripts/audit-escape-sync.py` has one) and the compact-contract captures in
   `design/`. They are read by no gate today, so they cost nothing, but a
   receipt without a producer is a receipt that cannot be refreshed.
