**Live:** https://tsunami.nonarkara.org
**Repository:** https://github.com/Nonarkara/tsunami-evacuation
**State at handover:** `main` = `54a2793`, pushed to GitHub, deployed to Cloudflare

This note is for whoever picks the project up next. It says what the thing is, what
it is allowed to claim, how to release it, and what is still unproven.

---

## 1. What this is

A research-informed **planning pilot** for Khao Lak and the Gulf of Thailand coast.
It turns one published preprint into planning views and a separate terrain-and-crowd
research exercise.

**It is not** an alert service, a validated evacuation routing tool, an inventory of
approved refuges, or a replacement for the author's Unity simulation. It says so on
the page, in every surface, and in `docs/RESEARCH.md`. Keep saying it.

Five surfaces, one path each:

| Surface | The task | The path |
|---|---|---|
| **Model** | see what the model does under your assumptions | pick area → set pace/people/route → Start → read the result |
| **Plan** | write down your own plan | fill the fields → tick the readiness checklist → save on this device |
| **Drill** | run a drill and record it | record counts → note what to change → save → read the protocol beside it |
| **Research** | check the evidence | methods, sources, validation, the unresolved inconsistency, the DDPM evidence |
| **Manual** | how to use any of it | `?` in the masthead, opens as a native dialog |

## 2. The rules that are not yours to break

`AGENTS.md` is the binding contract for this codebase. Read it before changing
anything. The rules that bite hardest, and why:

1. **Never infer live tsunami safety** from an earthquake, from elapsed time, from
   the nearest OSM building or from a straight line on the map. There is no live
   warning feed here. If someone asks "is this building safe?", the answer the app
   gives is that no height establishes safety, and it must keep giving it.
2. **No invented hazard, route or refuge GIS.** Everything drawn comes from a
   sourced snapshot with a recorded receipt.
3. **Only explicit source heights may extrude.** The 4 November 2026 owner rule
   supersedes the earlier 3 m massing permission: a building with no stated height
   is flat, and a floor-derived estimate is recorded but not drawn as a height.
4. **A point-queue model has no physical crowd footprint.** Never jitter, spiral or
   scatter waiting agents to look like a crowd. Counts aggregate at their exact
   network nodes and weighted totals must conserve the population.
5. **Wave time is not a walking deadline.** Warning-relative schedules and
   earthquake-relative wave times are not comparable, and the app must not compare
   them.
6. **Colour may never imply safety.** Amber means "act", not "you are safe".
7. **Preserve the map, charts, planner, drill protocol, citations and entered
   data.** Never collapse a file by more than 30 % without explicit approval.
8. **Do not fix a layout problem by deleting content or adding a spacer.** The MSH
   law is `/Users/nonarkara/Projects/MSH.md`: spatial hallucination is an interface
   inventing a reason to occupy space. Repair the geometry, keep the content.
9. **Do not frame, proxy or rewrite the third party's Rokehan tool.** Its CSP sets
   `frame-ancestors` to its own domains; the link opens in a new tab on purpose.

## 3. Running it

```sh
npm ci
npm test          # 88 TypeScript tests + 11 Python tests
npm run build     # tsc -b && vite build
npm run dev       # local dev server
npm run preview   # serve the build
```

Deploying is `npm run deploy`, which runs the tests, the build and the contrast
check before `wrangler deploy`. Deploying to a static host is Cloudflare Workers
with static assets (`wrangler.jsonc`, assets from `./dist`).

Before you call anything live, run all three and record the numbers:

```sh
npm test
npm run build
node scripts/check-contrast.mjs
```

Then take fresh receipts against the **deployed** site and re-run the gates:

```sh
python3 tools/viewport/capture.py https://tsunami.nonarkara.org
python3 tools/viewport/msh-capture.py https://tsunami.nonarkara.org
node scripts/check-viewport-evidence.mjs
node scripts/check-banner-evidence.mjs
```

A receipt is only evidence for the surface it actually measured, and only for the
bytes it actually saw. `docs/evidence/viewport-2026-10-28/live-bytes.json` records
the sha256 of what the host served at capture time; compare it with your local
build before quoting a receipt as current. **A pass that was measured against an
older bundle is not a pass.**

Sign commits with `Agent: <the actual agent>`.

## 4. The evidence receipts, and what they do not prove

`tools/viewport/` holds a read-only collector, a capture driver and an MSH
instrument. The instrument reports, per viewport, the chrome cost, the geometry
failures, the holes **inside** a reading column and the tail at the end of one.
It cannot see inside a paginated column, which is why the collector merges the
visible block rectangles of the visible column rather than trusting the DOM.

Two more instruments joined it on 12 November:

- `tools/viewport/bands.py` reads the **rendered lines** of a text band — the exact
  characters on each line, the measure in characters per line, and whether the last
  line is a stranded word. It is what found the six stranded words recorded in
  `docs/MSH-AUDIT-2026-11-12.md`.
- `scripts/verify-components.py` drives a built site in Chromium and checks the
  components a release would be broken without: the terrain reaching a ready state,
  the water re-shading as a replay advances, the roster conserving its total, a drill
  record surviving a reload, the research index resolving, the data-and-sources
  dialog staying inside the viewport, the masthead being one row at seven widths,
  and every section having its own navigation symbol.

The receipts are necessary and not sufficient. Two of the faults found in the last
week were invisible to the gates:

- the drill protocol rendered at **20 characters a line** at 1440 and 14 at 1024,
  and every gate still passed;
- the wave shading **did not move at all** between two frames of the same event,
  and the code was correct — the scale was wrong.

Both were found by measuring the rendered pixels, not the source. The gates know
about geometry; they do not know whether the thing on screen means anything.

## 5. What is proved, and what is not

**Proved by measurement.**

- The wave is shaded by the depth the model gives for each cell, on one scale for
  the whole imported file. Between frame 0 and frame 1800 s of a synthetic replay,
  **100 %** of the water pixels move, by a mean of 31 red levels, and the change
  differs from cell to cell. Before the fix: 0.1 % of pixels moved by 0.08 of a
  level. See `docs/WAVE-AND-DRILL-PATH-2026-11-07.md`.
- The drill protocol reads at 70 characters a line with its heading and its five
  steps kept together, and the page height is unchanged.
- Roof shapes come from the OSM snapshot's own `roof:shape` tags (7 ways) and from
  one dated aerial-image reading, kept apart by provenance, with a receipt for
  each. Ridge lines are drawn in plan because no height is known.
- The Rokehan permalink carries this app's own state: the sourced OSM camera node,
  the sun at that place mapped onto the tool's four time-of-day bands, the camera
  in use as the tool's own menu values, and its Thai interface when the app reads
  Thai. It opens in a new tab because the tool's CSP forbids framing.

**Not proved. Do not claim these.**

- **No real research replay ships with the app.** Only the schema, the import path
  and synthetic fixtures. Every wave measurement above is against a fixture whose
  own title says it is not hazard evidence. The mechanism is proven; what a real
  model would draw is unknown.
- **No physical-phone test.** The shortest viewport used is 320 × 568 in
  emulation; Safari with real toolbars was emulated at 390 × 664. A phone in the
  hand has not been used.
- **Roof coverage is 8 readings for 1,196 buildings** (0.7 %). Esri World Imagery
  has no z19 over Khao Lak — z19 and z20 tiles are byte-identical placeholders —
  and z18 at 0.59 m/px is all there is. The 30/60 cm sub-layers need a blocked
  export endpoint. This is a source ceiling, not a shortcut.
- **No community-language reading test** of the pagination controls in Thai.
- **The Rokehan embed** needs one line changed by that tool's author
  (`frame-ancestors 'self' https://oyasumi-gamedev.com https://tsunami.nonarkara.org`).
  Until then the link opens in a new tab, and that is correct behaviour, not a bug.

## 6. What to do next, in order

1. **Get a real replay in.** The schema is `public/data/hazard-replay.schema.json`:
   warning-relative seconds, EPSG:4326 cell bounds, north-to-south rows, MSL datum,
   depth in metres, and a wave gauge with its own location and a crest-to-trough
   definition. Load it through *Research → Load research inundation frames*. It
   stays on the device and is never uploaded. Check that its depths are the
   numbers you expect before showing them to anyone.
2. **Look at it on a phone.** The shortest viewport has never been a real phone.
3. **Close the roof coverage** if it matters: the sub-layer export endpoint, or a
   higher-resolution imagery source for the Khao Lak tiles.
4. **Read `docs/RESEARCH.md` and the open items in `docs/MSH-AUDIT-2026-11-06.md`**
   before changing any number that came from the preprint. Every published result
   must keep its scenario, source and historical modelled tier.

## 8. The 12 November release

What changed after the 7 November handover, and what it is worth knowing before you
touch any of it. The full audit is `docs/MSH-AUDIT-2026-11-12.md`.

**The navigation now has five section symbols.** The DDPM risk-evidence page owns
one, as `AGENTS.md` asks. It used to be filtered out of the navigation console and
was reachable only from a link inside the Research index. The symbol opens the page,
and the page is marked current while it is open.

**The map caption says what it means.** The scope qualifier was being interpolated
as JSX inside a template literal, so the caption printed the literal text
`[object Object]`. It is now an element, and it reads *(practice only)*.

**Six stranded words are gone.** Each was a single word alone on the last line of a
text band — "only", "unapproved" twice, "guidance.". A qualified term now breaks as
a unit. Measured at 390, 1024 and 1440: no stranded word, no prose block under 40
characters a line.

**One quantity, one name.** The same 4:34 was "max link wait" in the readout, "Max
segment wait" in the chart legend and "max wait" on the chart marker. It is now
*max wait*, *wait per segment* and *max per segment* — three names for three
distinct quantities.

**One qualification, said once.** "endpoint unapproved" was on the screen four times;
it is now only on the exercise-boundary line, which is unconditional and sits under
the controls. Each of the other places keeps its own distinct claim.

**Dead rules are gone.** Eight selectors and four keyframe sets with no use, two of
whose names asserted that something was safe. Nothing in the stylesheets now names a
thing safe.

**Two things that look like faults and are not.**

- The exercise clock runs slower than wall time on a software renderer.
  `advancePlayback` ignores any frame gap over 250 ms by design, so a rendering
  stall cannot jump the clock ahead. On a normal GPU the clock runs at the selected
  rate. Do not "fix" this by removing the cap.
- The crowd legend is a grid, not a wrapping row, and it changes its column count
  with the width of its container. It looks inconsistent between 1024 and 1440
  because it is: four states, two columns when narrow, four when wide, and the
  column count always divides the count.

**Still not proved.** The physical-phone test and the Thai pagination reading test
are outstanding — every width in the record is an emulated viewport. Roof coverage is
still 8 readings against 1,196 buildings. No real research replay ships with the
app. The Rokehan embed still needs one line changed by that tool's author.
